## 1. Problem & intent

The Weaver Target Studio's Author stage is twelve free-text fields plus hand-written openCypher — every value (targetId token rules, `missing_<gap>` column names, per-action required fields, `row.<column>` templating, the key-composition idiom in the RETURN) must be known from memory, and validation arrives only on a server round-trip. It is operable by us; it is not operable by an operator.

The intent: the operator writes **what they want in plain language**; the platform authors the structured target; the human reviews, optionally edits in the Author form, approves. The NL intent persists onto the installed target as its `.description` aspect, so the roster answers "what is this?" forever after. *(Scoped at Phase 0, 2026-08-21: the shipped pipeline records ONE artifact per authoring request — `RecordCapabilityProposal` decodes a single `{kind, content}` — so v1 authors a `weaverTarget` bound to an **existing installed lens** from the catalog; an intent needing a NEW violation lens gets the target draft plus the proposed lens sketched in the rationale, finished by the operator in the Author form via Load-into-Author. Widening the replyOp to multi-artifact is a pipeline change outside this ratified scope.)*

## 3. The shape

### 3.1 `cmd/model-runner` — the model-call service (new binary + `internal/modelrunner`)

A queue-group NATS service, deliberately **domain-free**: it knows how to call a model vendor safely; it knows nothing about capabilities, targets, or the Augur.

- **Service surface:** a NATS micro-service endpoint (queue group `model-runners`) on a `svc.model.*` request subject. Request = `{ref, model, system, messages/tool-schema, maxTokens}`; the runner **acks acceptance immediately** `{accepted, ref}` and works async. Wire types + subject names + a client helper live in a small leaf package (`internal/modelrunner/wire`) the bridge imports — `internal/bridge` itself stays SDK-free and pkgmgr-free. (The `micro` framework version-checked against our pinned `nats.go` per the vendors rule; new `docs/vendors.md` row for the Anthropic Go SDK, runner-side.)
- **Vendor call:** the official Anthropic Go SDK (`github.com/anthropics/anthropic-sdk-go`), streaming under the hood with final-message collection so long thinking turns don't trip HTTP idle timeouts; strict tool schema (`strict: true`, `additionalProperties: false`) so the model can only emit the caller's declared output shape; JSON parsed, never string-matched.
- **Result return:** the runner writes the completed result (or terminal refusal/failure) to a bootstrap-provisioned KV bucket `model-results` at key `<ref>` — the caller polls it (§3.2). A **CAS-created in-flight marker at the same key** is the double-spend guard: a redelivered dispatch for a ref already in-flight or done acks without a second vendor call (the substrate-level twin of the fake's memoization).
- **Caps + accounting (runner-side, global):** per-call `maxTokens` ceiling, daily call cap from env, usage tokens + call counts to Health KV (`health.model-runner.<instance>` — the sanctioned direct write). Over-cap or no-capacity replies transient-busy; the vendor key is redacted from every error string (named review item).
- **natsperm:** new matrix rows — the runner may subscribe its `svc.model.*` endpoint, write only `model-results` + its own Health; the **bridge** (the caller — checked per house rule) gains request-publish on `svc.model.*` and read/delete on `model-results`. No Core KV access for the runner at all.

### 3.2 The real `capabilityAuthor` adapter (bridge-side, thin)

Same `Adapter` interface, registered in `cmd/bridge/main.go` behind an explicit env opt-in (default: the fake, byte-identical to today). Constructor-injected, following the `NewFakeDocGen(conn, bucket, cap)` precedent: the wire client, a **catalog source** (reads the `capability-author-context` bucket — a lens read, P5-clean), and a **validator closure** built in `cmd/bridge/main.go` from the same three `pkgmgr.ValidateCapabilityArtifact` dependencies Loupe's `freshCapabilityVerdict` constructs (`cmd/loupe/review.go:551-569`).

`Execute`: assemble catalog + `catalogHash` → prompt (intent + catalog + authoring rules) + `promptHash` → dispatch to the runner → return `Dispatch{Pending, Ref}`. `Poll(ref)`: read `model-results.<ref>`; on a completed draft, run the **deterministic validator**; if invalid, one bounded repair dispatch (validator errors fed back; ≤2 model calls total, still under the runner's caps) → emit `CapabilityAuthorProposal` with the *computed* verdict (valid or invalid — never self-attested), real hashes, model id, and `description` distilled from the operator's intent so the installed target carries it. Refusals map to `OutcomeFailed` (terminal, recorded `invalid`); runner-down/no-responders and transient-busy map to `error` → Nak-with-delay; a result that never lands hits the shipped `CallDeadline` timeout. Going async requires the `capabilityAuthor` pattern to declare a `DispatchOp` — a new create-only DDL op mirroring lease-signing's `RecordServiceDispatch` precedent (`capability-author` package bump).

### 3.3 Catalog widening (package edit, `capability-author` bump)

`capabilityAuthorContext` today projects only op self-description columns. Add `spec` and `description` to its projection so the author sees: existing lens bodies (what cypher looks like here, which columns exist), existing weaver-target bodies (style + collision avoidance), and — post the `.description` fire — every target's prose (style examples). The reader filters by class; the lens stays one `MATCH (m:meta)`.

### 3.4 The Loupe half — Describe + edit loop (Loupe lane, Winston-adjudicated UX)

- **Describe panel** on `#/weaver/author`: one textarea + Submit → `POST /api/weaver/author/request` → relays `RequestCapabilityAuthoring` via the Gateway under the operator's token (permission `operator @ any` already granted). The panel links to the review queue where the draft will appear.
- **"Load into Author"** on a weaverTarget-kind proposal detail: hydrates the Studio form from the proposal's artifact `content` (the inverse of the propose mapping — including `description`), so the operator edits, re-checks, and re-proposes as an operator-source proposal; they reject the AI draft from the same screen. Review stays approve/reject/apply for unedited drafts.

### 3.5 Why async-primary (and why not an embedded client)

The bridge's events consumer must not block for a 1–3 minute model turn (AckWait/redelivery pressure) — the shipped Pending/poll path exists precisely for slow external work, and the parked row's premise is that real adapters ride it. A synchronous long request/reply is rejected for the same reason. The rejected earlier draft — SDK client embedded in the bridge — would have made the bridge the secret holder, serialized model work behind its consumer, and left the Augur to duplicate the substrate; the queue-group runner gives credential isolation, horizontal scale, and one shared egress instead. The Batches API (50% cost, minutes-scale) is a natural runner-internal follow-on and changes no caller; explicitly deferred.

## 6. Risks & self-adversarial pass

- **Prompt-injection via the catalog** (a lens description authored by a tenant flows into the prompt): the catalog is meta-vertex self-description written by package authors/operators, not tenant data; the output can only become a *proposal* that deterministic validation + human review + the protected-package guard bound. Residual accepted.
- **Model emits a plausible-but-wrong target** (valid shape, wrong semantics): unchanged trust model — same risk as a human author today; the review console + Trial panel (born-disabled targets) are the containment. The `description` on the draft makes wrongness *legible*.
- **Key isolation:** the credential exists only in the runner's env — never in the bridge, Loupe, KV, or logs; redaction is a named NL-1 review item. Compromise of any other component yields no vendor key.
- **Runner fleet down / no responders:** requests Nak transiently and eventually hit the shipped `CallDeadline` timeout — the exact machinery every external adapter already lives under; nothing hangs, nothing is lost (the JetStream events stream holds the work).
- **Cost runaway:** idempotency memo + Weaver anti-storm mark (dispatch-side) + the runner's CAS in-flight guard + daily cap + `max_tokens` — five independent bounds, three already shipped.
- **Rejected alternatives:** Loupe calling the model (console holding spend keys; bypasses request/claim provenance); the bridge embedding the SDK client (§3.5 — the superseded first draft of this very doc).
